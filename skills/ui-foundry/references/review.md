# 审核与修复

## 最低证据

原始要求先于实现。验收结果不能从已经做出来的东西倒推。

| ID | 判断 | 最低证据 |
| --- | --- | --- |
| intent | 做的是当前请求吗 | 请求、最近纠正、实际产物和保留项的对应 |
| task_flow | 完成真实任务且减少无效工作吗 | 实际输入 → 操作 → 领域结果；重要流程至少两种条件，核对结果而非只看 toast |
| visual | 构图、排版、密度与表达适合任务吗 | 当前渲染和真实视口；具体长处与缺陷；改版尽量比较同内容前后 |
| preservation | 原有功能和数据完整吗 | 受影响核心路径；未保存内容与切换、相邻操作、返回组合验证 |
| platform | 行为符合目标平台吗 | Web 的键盘/触摸，或原生设备/模拟器操作；说明环境 |
| claims | 状态与对外交付说明真实吗 | 草稿、模拟、执行、错误及已验/未验范围的实际证据 |

截图证明静态状态。动画证明变化发生。成功消息证明显示了消息。它们都不能单独证明业务结果已保存。需要持久化时刷新或重启核对；不需要持久化的试验不能捏造后台。

检查相关 Tab 和空态，不只看主屏。必要时覆盖长内容、加载、错误、取消、重试、焦点和键盘遮挡。不要为了填满清单添加无关功能或运行整套无关测试。

## 独立判断

大改有独立审核者时，先给原始任务、当前产物、平台和保留项，不先提供自评分或期望通过的结论。请审核者提出最重要的反例路径与具体视觉观察；只看图的审核者不能签功能通过。

没有独立审核环境就自己按相同要求检查，标明方式。审核者身份不等于证据；出现分歧回到可复现状态，而不是投票平均。

美观需要正向依据，例如主次构图如何服务任务、真实长内容如何保持阅读节奏、状态之间如何连续。只有“干净”“没溢出”不足以通过高品质设计要求。任何已确认的关键缺陷都不能被其他维度的长处抵消。

## 判定与返工

`pass`、`rework`、`unverified`、`not_applicable` 是人工观察结论。发现具体不符合要求时返工；缺证据时补证据，不盲目换色。第三轮仍失败时重审方法和假设，继续完成已授权的修复。

每次只修最重要的 1–3 个问题，重跑原失败路径及受影响的回归。保留失败历史和本轮差异；不重置轮数，不用同一证据冒充新验证。

外部权限或运行环境阻塞时完成安全的独立工作，准确交接未验项；不把阻塞解释成产品完成。

## 可选记录工具

小修可在现有记录写观察，不必六项 JSON。大改缺现有格式时复制 `assets/review-record.json` 到项目自己的证据目录。该模板全部为 `unverified`，必须替换占位证据后才能作真实记录。

```sh
python3 scripts/check_design_gate.py /path/to/review.json
```

命令路径相对本 Skill 目录。Python 3 只用于可选格式校验，核心设计流程不依赖它。脚本只读指定的本地 JSON，不联网，不读凭据，不修改文件。

退出码：0 汇总为 PASS，1 记录无效，2 汇总为 REWORK，3 汇总为 UNVERIFIED。`quality_verified_by_script` 始终为 `false`；脚本不核实证据、渲染或审美。CI 可以验证记录格式或脚本单元测试，不能称为设计合格认证。
