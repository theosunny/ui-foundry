# 0.1.0 验证记录

日期：2026-10-27。范围：公开 Skill 包、审核记录校验器及独立行为检验。**本次不是成品 UI 审美验收。**

## 可复现检查

- `python3 -m unittest discover -s tests -v`：15 项通过，覆盖记录判定、失败不能平均掉、未知不能放行、包文件边界、相对链接、隐私模式和许可证一致性。
- skill-creator 的 `quick_validate.py`：通过。依赖 PyYAML 由临时工具环境提供，不加入 Skill 运行依赖。
- 空白审核模板：退出码 3，`reported_verdict: UNVERIFIED`，`quality_verified_by_script: false`。
- ClawHub CLI 0.23.3 发布预检：`would-publish`，8 个发布文件；这不等于上传完成或平台审核通过。

这些自动检查不判断美观，也不能证明所有隐私内容必被模式检测识别；公开材料另做人工只读审查。

## 独立行为检验

审核者从新上下文读取公开 Skill 和必要参考，只获得用户请求与原始场景事实，没有得到预期答案或实现者自评分。所有场景使用虚构内容，没有操作真实产品。

| 场景 | 首轮观察 | 修订及复测 |
| --- | --- | --- |
| 高频财务录入表 | 保留同页四字段，但自行添加正金额限制及保存后清空行为 | 增加“设计选择不等于业务规则”的约束；新审核者在负金额调整表中保留负数、不擅定零值规则，要求核对既有存储和行为 |
| iPhone 食材提醒任务书 | 没有假装拍照识别，但默认到期日为七天后，首版扩出过多管理功能 | 区分未知事实与可逆默认，收敛最小路径；新审核者要求日期来自包装、移除扩展模块、明确没有运行设备或通知测试 |

摘录见 [观察记录](../evals/observations-0.1.0.json)。复测支持这些特定行为改善；不能外推成模型始终遵守规则，也没有证明每个默认提醒策略或导航安排都是最佳选择。

## 发布审查与边界

- 独立审查曾发现测试导入错误与缺失验证文档；已修复。保留失败记录，避免将首次检测说成全绿。
- 公开目录不包含私人偏好档案、聊天记录、账号凭据、真实用户资料或本机主目录路径。保留源项目链接作为方法致谢，没有捆绑其原始 Skill 或代码。
- 本次没有新增、渲染或实际操作 Web / 原生 App；视觉品质、设备行为、生产部署与不同客户端的自动触发均不由这些检查证明。
- 历史私人产品试验不随包发布，也不当成通用审美认证。GitHub / ClawHub 的实际发布结果另行核对。

复测方法：从 [场景文件](../evals/cases.json) 选择请求，只把 `request` 和 `fixture` 交给独立执行者。保留 `review_criteria` 给审核者；核查真实输出。产品实施试验还须提供可运行产物与渲染/操作证据，不能只阅读计划。
