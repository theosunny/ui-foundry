# Foundation attempt and repair

The first foundation forward run used a fresh agent context and the public candidate instructions. It passed the nine schedule behavior checks, but remained **REWORK for interaction/composition**: an event title, summary, guidance and duplicate form information pushed the phone's note/save controls below the first viewport. Its output and report remain in `B/schedule/`.

This exposed a routing/execution gap: supplying a visual recipe document did not ensure the agent applied the concrete foundation. The revision adds a runnable original reference and explicitly routes new web designs through that real artifact, adapting its structure to the task. The maintainer implemented the repair in `repair/B/schedule/`; this is an authored correction, not an independent initial-generation win.

The repair shows the title once as an editable object name, groups date/time, keeps note and save in the tested phone viewport, and retains object switching. The same nine functional checks pass. A new reading-queue task tests whether the revised material transfers beyond this tuned schedule example; it is not a controlled claim of general superiority.

Separately, foundation CSS browser tests initially found two failures: muted-text contrast 4.48:1 and a stretched native checkbox. Both failures and initial screenshots remain in `primitives/`; corrected evidence is in `primitives/repair/`. The fix darkens the muted token and excludes checkbox/radio from full-width text-input styles. All six bounded checks then pass. These are component integration observations, not proof of aesthetic quality or a full accessibility audit.

## Independent revision review

A fresh reviewer compared anonymous original/corrected screenshots and preferred the corrected composition, while flagging weak title-edit discoverability and the clipped mobile selection strip. These were not ignored: the next revision exposes the title label and places all three known events in a visible mobile row. That revision is preserved in `final/B/schedule/`.

On reinspection the reviewer gave **pass within static scope**: all three objects are identifiable, the form follows date/time → location → note → save, and mobile keeps the full core task above the fold. Minor compromises remain: metadata truncates in small selection cells, the pencil is only a visual cue (the input has a real label), and desktop has generous lower whitespace. The review cannot prove persistence or control semantics; the browser checks are separate.
