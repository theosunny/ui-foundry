# 审核与修复

## 最低证据

原始要求先于实现。验收结果不能从已经做出来的东西倒推。

| ID | 判断 | 最低证据 |
| --- | --- | --- |
| intent | 做的是当前请求吗 | 请求、最近纠正、实际产物和保留项的对应 |
| task_flow | 完成真实任务且减少无效工作吗 | 实际输入 → 操作 → 领域结果；重要流程至少两种条件，核对结果而非只看 toast |
| visual | 构图、排版、密度与表达适合任务吗 | 当前渲染和真实视口；具体长处与缺陷；改版尽量比较同内容前后 |
| preservation | 原有功能和数据完整吗 | 受影响核心路径；未保存内容与切换、相邻操作、返回组合验证 |
| platform | 行为符合目标平台吗 | Web 的键盘/触摸，或原生设备/模拟器操作；说明环境 |
| claims | 状态与对外交付说明真实吗 | 草稿、模拟、执行、错误及已验/未验范围的实际证据 |

截图证明静态状态。动画证明变化发生。成功消息证明显示了消息。它们都不能单独证明业务结果已保存。需要持久化时刷新或重启核对；不需要持久化的试验不能捏造后台。

检查相关 Tab 和空态，不只看主屏。必要时覆盖长内容、加载、错误、取消、重试、焦点和键盘遮挡。不要为了填满清单添加无关功能或运行整套无关测试。

有常用业务控件时，核对其语义和服务：地点是选定对象还是未解析文本、纯日期是否跨时区漂移、搜索迟到响应和中文输入法是否误提交。外部服务、组件库渲染、原生设备行为分别验收；示例数据能运行不能证明地图或生产 API 接通。转场应可打断、可减弱且不推迟真实操作。

声称“保留已有数据/契约”时，从原始契约选一条非默认已有状态实测，而不只运行新用户演示数据。例如允许的空列表不能被初始化逻辑重填。缺少工具时记录实际尝试与阻塞；若有已授权的其他验证方式，继续补证据，不把一次入口失败当成全部验证不可做。

## 独立判断

大改有独立审核者时，先给原始任务、当前产物、平台和保留项，不先提供自评分或期望通过的结论。请审核者提出最重要的反例路径与具体视觉观察；只看图的审核者不能签功能通过。

没有独立审核环境就自己按相同要求检查，标明方式。审核者身份不等于证据；出现分歧回到可复现状态，而不是投票平均。自动测试报错也先核对测试前提：例如初始化脚本不能在刷新时重置被测持久化数据。修测试与修产品分开记，不为消除误报改坏正确行为。

美观需要正向依据，例如主次构图如何服务任务、真实长内容如何保持阅读节奏、状态之间如何连续。只有“干净”“没溢出”不足以通过高品质设计要求。任何已确认的关键缺陷都不能被其他维度的长处抵消。

## 可复制的质量标准

在实现前选择本次适用的指标，记录条件和实际值；不要给未测项目填满分。

| 维度 | 可测内容 | 返工信号 |
| --- | --- | --- |
| 用户工作 | 完成同一任务必须重新键入的已知信息、额外决定、离开当前上下文的次数 | 重复采集；只删文字却增加找入口或手工整理 |
| 任务闭环 | 至少两种输入下，从开始到真实结果；取消/返回；需要时刷新核对 | 数据丢失、假成功、主要路径无法收尾 |
| 发现与反馈 | 首次动作是否可找到；操作后能否确认新状态；键盘路径 | 核心动作依赖隐藏悬停；同一事实重复展示挤走动作 |
| 视觉落实 | 所用色值、字号、间距与状态是否来自选定系统；同视口原图对照 | 未说明原因绕过底稿；层级无重点；复制模板后内容不合任务 |
| 可访问性 | 正文对比 4.5:1、焦点与名称、窄屏溢出、所支持动态/主题 | 已测关键文本不达标；键盘无法使用；控件尺寸或布局失效 |

计数是诊断，不是全局压低：必须决策和高效专家表单可以保留。视觉独立评审需给出具体构图、排版、密度、材质与连续性的优缺点及对比偏好，不能用量化指标冒充审美。无人体验过的页面不声称“用户五秒懂”“满意度高”或“获奖级已认证”。

## 判定与返工

`pass`、`rework`、`unverified`、`not_applicable` 是人工观察结论。发现具体不符合要求时返工；缺证据时补证据，不盲目换色。第三轮仍失败时重审方法和假设，继续完成已授权的修复。

每次只修最重要的 1–3 个问题，重跑原失败路径及受影响的回归。保留失败历史和本轮差异；不重置轮数，不用同一证据冒充新验证。

外部权限或运行环境阻塞时完成安全的独立工作，准确交接未验项；不把阻塞解释成产品完成。

## 可选记录工具

小修可在现有记录写观察，不必六项 JSON。大改缺现有格式时复制 `assets/review-record.json` 到项目自己的证据目录。该模板全部为 `unverified`，必须替换占位证据后才能作真实记录。

校验器随本 Skill 位于 `scripts/check_design_gate.py`。需要时由 Agent 定位当前实际加载的 `SKILL.md`，取它的父目录作为 Skill 根目录，并用完整路径调用脚本；审核记录同样传入实际路径。不要从被审查项目的当前工作目录寻找脚本，不要求普通用户执行。

维护者手动使用 POSIX shell 时，把以下示例路径替换为实际绝对路径：

```sh
UI_FOUNDRY_DIR="/absolute/path/to/installed/ui-foundry"
python3 "$UI_FOUNDRY_DIR/scripts/check_design_gate.py" "/absolute/path/to/review.json"
```

Python 3 只用于可选格式校验，核心设计流程不依赖它。脚本只读指定的本地 JSON，不联网，不读凭据，不修改文件。

退出码：0 汇总为 PASS，1 记录无效，2 汇总为 REWORK，3 汇总为 UNVERIFIED。`quality_verified_by_script` 始终为 `false`；脚本不核实证据、渲染或审美。CI 可以验证记录格式或脚本单元测试，不能称为设计合格认证。
