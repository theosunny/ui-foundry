# 场景组件：从用户任务到平台实现

当任务涉及日期、地点、搜索、选择、上传、导航或反馈时读取本页。Agent 负责选好并接通组件；用户只补充产品事实，不负责研究控件。组件选择必须完成到数据、状态和实际操作，不能在设计稿中放一个输入框就算实现能力。

## 选择顺序

1. 从项目确认平台及运行方式：桌面/移动 Web、SwiftUI、Compose，或已有 React Native/Flutter。按实际技术栈适配，不根据屏幕宽度猜成原生 App。
2. 判断任务：搜索已有对象、选择固定值、创造内容，还是调用系统/外部服务。先用已知数据和熟悉控件，保留必要的直接输入。
3. 复用已接受的组件系统。新 Web 使用兼容的成熟组件；iOS/Android 使用平台组件。下表是默认路由，具体 API 先核对项目锁定版本。
4. 实现数据契约、加载/空态/失败/取消与恢复，再接视觉 token、焦点和转场。没有服务配置时保留可用的手动路径，明确未接通部分。
5. 验证真实保存结果以及一个失败/中断条件。可运行示例、模拟服务和已接通生产能力分别说明。

## 通用组件契约：先定义行为，再选外观

每个交互组件都要有同一份最小契约，不因它是地图、看板或 AI 对话而省略：

- **意图与结果**：用户在做选择、浏览、编辑、提交还是确认？成功后哪个可观察结果改变？查询词、草稿和已提交值不可混为一个字段。
- **语义数据**：保存 ID、数值、日历日、时刻+时区、排序或权限状态等真正业务值；显示文案、格式化金额和临时动画不是数据源。未知、空、零、手动值与已解析值分别建模。
- **已知上下文**：复用当前对象、筛选、时区、设备能力、最近选择和已有权限；只在缺少决定所需事实时询问。默认值不能伪造用户意图。
- **状态与恢复**：至少判断 loading、空结果、失败、取消、提交中和成功后的去向。风险操作给出后果、撤销或明确恢复路径；异步完成前不能伪造成功。
- **平台与可达性**：键盘、触摸、焦点、读屏、返回/Escape、缩放、减少动态效果与隐私授权都是组件行为的一部分。系统组件优先继承这些能力。
- **可观察检查**：在实际运行中确认输入、选择、取消、保存、失败重试和返回后数据；检查一个窄屏/触摸或键盘路径。组件能 import 不代表任务可完成。

按任务取适用项，写进现有设计记录即可；简单控件不另造六份文档，不为填满状态表虚构加载、审批或向导。

## 决策路由：成熟行为优先，必要时受约束地创作

1. **高频且平台已有熟悉语法**：优先内置/系统组件。例如日期、文本输入、文件选择、权限、导航、选择列表、弹层、焦点和系统返回。
2. **项目已有成熟设计系统**：复用其可访问的 primitives 和 token；只补缺失能力，不同时引入两套重叠基础库。
3. **任务需要独特信息结构或直接操作**：可自定义组合与视觉语言，例如空间画布、排程、作品审阅、复杂数据探索。但先写清以上契约，并保留成熟替代路径（例如拖放也可通过菜单/键盘移动）。
4. **没有可靠平台或库答案**：模型可以发明控件，但必须说明为何现有模式不能满足任务、如何学习和撤销、怎样处理失败及如何测试。新颖不能靠隐藏常用行为或加长引导文案成立。

这不是“禁用输入框、表单或向导”的规则。自由写作、精确数据录入和真正分步的高风险流程仍应使用它们；目标是减少无意义的选择与重复输入，不是把每个任务伪装成自动化。

不固定全局颜色、字体、动效或组件库。模型可在产品品牌与任务约束内发挥；熟悉行为、可恢复状态和真实结果是不可降低的底线。

## 常见任务的默认路由

| 用户任务 | Web | iOS / SwiftUI | Android / Compose | 交付要点 |
| --- | --- | --- | --- | --- |
| 选某一天 | DatePicker + 可直接编辑的 DateField | DatePicker，按场景用 compact / graphical | Material 3 DatePicker + DatePickerDialog | 存日期值，支持取消；生日不默认今天；高频录入保留键入 |
| 选日期范围或时间 | DateRangePicker / TimeField | 日期范围约束 + DatePicker 时分 | DateRangePicker / TimePicker | 明确时区、跨日、起止关系；未知规则不擅自增加限制 |
| 找地点、选会面位置 | 可搜索候选 + 选定详情；需要核对位置时显示地图 | searchable 列表 + MapKit 或已接入地区 SDK | SearchBar / 搜索页面 + 已接入地图 SDK | 保存地点对象；地图需真实数据，不能用装饰底图代替 |
| 搜索/筛选已有内容 | SearchField、结果列表、可撤销过滤条件 | searchable + List | Material 3 SearchBar + LazyColumn | 本地即时筛选，远端取消过期请求；保留滚动和返回上下文 |
| 少量单选/多选 | RadioGroup / CheckboxGroup / Segmented control | Picker / Toggle，适当 pickerStyle | Single/MultiChoiceSegmentedButtonRow / Checkbox | 选项能扫读；不把两三个常用选项藏在搜索弹窗里 |
| 大量对象中选一个 | ComboBox / 可搜索 Select | 可搜索选择列表，明确选中与返回 | 搜索选择页 / ExposedDropdownMenuBox | 显示身份区分信息；输入词不等于已选择对象 |
| 数量、金额、范围 | NumberField / Stepper；Slider 只用于近似调节 | Stepper / 格式化 TextField / Slider | 合适键盘 TextField / Slider | 单位、精度与小数语义正确；不能用滑块强迫输入精确金额 |
| 上传、拍照、附件 | file input + 拖放补充 + 预览/进度/重试 | PhotosPicker / fileImporter | 系统 Photo Picker / Storage Access Framework | 类型与大小限制、取消、实际上传状态；不默认索取完整相册权限 |
| 写作或编辑内容 | 就地编辑 / TextArea，已有编辑器优先 | TextEditor / 系统文本输入 | TextField，支持多行与 IME | 草稿保留；键盘不遮挡操作；长文不强拆向导 |
| 导航与切换对象 | 路由/列表、必要的 Tabs；适配窄屏导航 | NavigationStack、TabView、返回手势 | NavigationBar、NavigationRail、Navigation Compose | 状态可恢复；移动 Web 的返回仍是浏览器语义 |
| 次级详情/短编辑 | Popover / Dialog；小屏按需要用 sheet | sheet / confirmationDialog | ModalBottomSheet / AlertDialog | 焦点进入/返回，Escape/系统返回，取消不写入；不多层套弹窗 |
| 提交/删除/异步任务 | 原位状态 + 必要 toast/Undo；可恢复错误 | 原位反馈、适当 haptic、confirmationDialog | SnackbarHost/Undo、进度、AlertDialog | 先完成真实变更再报成功；撤销恢复原对象；破坏性后果行动前可见 |

## 其他任务族：按契约扩展，不靠堆组件

| 任务族 | 默认模式 | 必须定义的边界 |
| --- | --- | --- |
| 图表、指标、数据表 | 先给结论与可比较的图表；明细用可排序/筛选表格 | 口径、单位、时间范围、缺失值与加载来源；不把装饰图当证据 |
| 批量选择与批量操作 | 行内选择 + 明确选择计数 + 上下文操作条 | 全选范围、不可操作项、执行前影响、部分失败和 Undo/结果明细 |
| 看板、排程、拖放 | 拖放直接表达空间/顺序才使用 | 键盘/菜单替代、移动后保存状态、冲突与回滚；不能只靠拖拽完成核心任务 |
| 富文本、媒体编辑 | 复用项目已有编辑器或平台编辑能力 | 草稿、选区/焦点、上传处理、损坏/失败恢复；不把 Markdown 预览冒充编辑器 |
| 登录、授权、设置 | 走已有认证与系统权限入口；设置就地保存 | 请求前解释必要性，拒绝后的手动路径，敏感变更的当前值与后果 |
| 上传、离线、长任务 | 系统选择器 + 真实队列/进度/重试 | 实际字节状态、断网、恢复、取消、重复提交与可用的本地草稿；未知进度不显示假百分比 |
| AI 流式生成、审阅、审批 | 流式内容是草稿，重要动作落在可审阅对象上 | 生成中/中断/失败、来源与不确定性、接受/编辑/拒绝、已有授权与必要批准；不得虚构已执行的自动化 |
| 支付、订单、订阅 | 复用合规支付/系统结算界面 | 金额、币种、周期、税费、续费/取消与最终确认；后果必须在付款前可见 |

这些是任务模式，不是“要把每种控件都做一遍”的待办。新领域先映射到最接近的任务族，再补充其特有数据和风险。

Web 的 HeroUI 是成熟交互基础之一，不提供地点数据服务。React Native 也不是把上述 Web React 组件放进 WebView；沿项目实际使用的原生模块和路由适配。Android API 的稳定性按锁定的 Compose Material 3 版本检查，不能只为消除编译错误盲目全局 opt-in。

## 地点：组件与服务一起完成

**先决定需要什么。** 线上会议可直接使用线上状态/链接；“去哪里”才需要地点选择。用户只想选择已有办公地点时先列出这些地点，不要求再搜地图。精确落点/路线确实影响决定时提供地图预览或导航。

**数据契约。** 查询文本、手动地点、选中的 POI 是三种状态。选中 POI 保留来源、名称、地址及服务提供的稳定 ID；服务不提供 ID 时明确缺失，不把本地 UUID 冒充供应商 ID。有坐标时保留数值与坐标系，数值 `0` 不是缺失。修改查询后不能暗中沿用旧 POI 的坐标。手动输入不伪装成已解析地点。

**地区与接入。** 中国大陆项目先检查已有高德/腾讯/百度能力及服务配置；没有既有服务时可采用本包的高德服务端适配起点。其他地区根据已有账号、平台和覆盖选服务；不因为是 Android 就默认依赖 Google Play Services。MapKit 是 Apple 平台路线之一，品牌/地域/数据契约仍需核对。GCJ-02、WGS84、BD-09 和不同供应商返回值不能直接混用；地图预览与导航必须使用匹配来源和坐标转换。

**查询与降级。** 远端建议通常以约 250ms 防抖起步，中文 IME 组合中不发请求；新查询取消旧查询，并拒绝迟到响应。显示加载、无结果和服务不可用的不同状态；保留输入、可重试、可明确选择手动地点。只有点击“使用当前位置”才请求定位，拒绝后仍能搜索或手动选择。

**服务配置。** 检查项目现有配置后复用。服务端 Key 留在服务端，客户端限制与服务端密钥不是一回事；地图 SDK 所需的 key、域名/应用限制、安全代理、额度、署名按供应商要求配置。缺少配置不搜索私人凭据、不擅自订阅，也不将返回假地点说成接通。服务端路由应继承宿主的鉴权、请求上限和频率控制。

包内 `assets/place-service/` 提供服务端适配，`assets/web-patterns/` 提供可注入 provider 的 UI。默认演示使用标注的示例地点，不联网；接入真实 provider 后，还要在目标项目检查真实结果与地图行为。原生示例位于 `assets/native-patterns/MeetingEditor.swift`，MapKit 网络结果和设备操作须单独验证。

## 日期与搜索：容易被外观掩盖的错误

- 日期值如 `2026-11-03` 是日历上的一天，不通过 `new Date(...).toISOString()` 绕一圈；跨时区可能变日。具体会议时刻另存时间与时区/instant。范围选择、时区、夏令时应按产品契约验证；默认日期不制造事实。
- 选择后显示可读日期，编辑时保持真实值，取消恢复已提交值。允许键盘操作，外部时区变化不能静默改动纯日期。
- 搜索要先区分“筛选本页”“从远端找对象”“选择一个值”。输入查询不自动提交业务选择；旧结果不能覆盖新结果；无匹配与数据本来为空使用不同状态。
- 快捷键是补充，不是唯一入口。中文组合输入的 Enter 不能触发保存/提交。清除查询恢复正确的完整列表，不清空已保存的数据。

## 动效服务状态变化

| 场景 | 默认处理 | 验证 |
| --- | --- | --- |
| 选中、按下、焦点 | Web 用约 120–180ms 的颜色/边界变化；原生优先系统行为 | 不抖动布局；不靠颜色单独表达选中 |
| 展开详情、sheet、弹层 | 延续来源位置，优先平台转场；Web 必要时约 180–240ms | 可打断，焦点和返回正确，不叠加第二套入场动画 |
| 过滤/排序/删除 | 保留对象身份；必要时短促位置过渡，Undo 恢复原位 | 快速连续操作不丢状态、不滚到顶部 |
| 加载/保存 | 即时给状态；已知进度才显示百分比，骨架保持结构 | 不人为等待动画播完才保存，不用假进度制造执行感 |
| 减少动态效果 | Web prefers-reduced-motion；原生跟随系统设置 | 移除非必要位移和循环，保留清晰的即时结果 |

时间是适配起点，不是所有产品统一播放规则。一个页面通常只需少量、有因果关系的运动。自动漂浮卡片、逐字播报标题、每个列表项入场、无意义发光和滚动劫持，不能代替产品交互。熟悉控件、真实内容、恰当密度与连贯反馈共同形成品质；“去 AI 味”不要求发明难懂的操作。

## 本任务的交付检查

写下所选组件与版本、数据从哪来、保存什么、失败怎样继续。验证核心控件的实际效果，而不是以组件 import 成功作结：地点换查询后不得保留旧坐标；日期刷新后不变日；搜索能取消旧请求；输入法不误提交；取消/撤销保留数据；键盘/读屏名称、焦点与触摸目标符合平台（iOS 至少 44pt，Android 通常 48dp）。

同一产品内使用一致的交互语法：相同的选择、保存、返回和错误恢复方式。用户可以从第一处操作学会其他地方，避免每个页面都重新解释。
