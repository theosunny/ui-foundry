# Blind static visual review

Scope: static screenshot review only. I inspected every supplied desktop and initial mobile image, without source, interaction, storage, or behavior checks.

## Repair quote comparison (`repair-choice`)

Preference: **variant 2**.

It makes comparison task immediately legible: each quote gives provider, rating, CNY fee, appointment, warranty, and a clearly bounded selection action. Card hierarchy is stable across desktop and mobile; calm off-white, green, and dark booking panel fit a practical local-services product. Local-demo/no-payment context is visible, and desktop uses secondary panel well without hiding primary comparison work.

Other variants:

- Variant 1: Clean, highly scannable desktop table. Mobile turns every option into a tall block, forcing important content below fold; selected-state/terms area is absent in initial mobile view.
- Variant 3: Strong editorial visual system and excellent CNY emphasis. Desktop headline consumes disproportionate vertical space; mobile initial composition shows a repeated/new header beginning immediately after two cards, which makes continuity look suspect.
- Variant 4: Desktop is polished and concise, but mobile has clear horizontal clipping: arrival values run past card edge. Blocker for a 390px requirement.

Visible limits: cancellation terms and selected confirmation state can only be evaluated after selection, which initial screenshots do not show. I cannot certify semantic controls, selection changes, persistence, unknown-field preservation, or vendor/payment behavior.

## Exhibit-note editor (`exhibit-notes`)

Preference: **variant 3**.

It best matches requested ink/white/coral exhibit identity while remaining an editor instead of a marketing page. On desktop, object list, active state, title/medium, credit, note field, save/cancel actions, and local-only context form a clear repeated-editing workspace. Mobile preserves the editorial hierarchy, keeps both objects reachable, and presents note editing with sufficient space. Coral use is restrained and consistently marks state/action.

Other variants:

- Variant 1: Beautiful typographic exhibit tone and strong factual hierarchy. Desktop leaves large unused lower area while editor controls are compact; mobile shows a second header beginning below saved state, harming page continuity.
- Variant 2: Compact, efficient editor. Visual language feels more generic product UI than collection/exhibit brand; mobile action row wraps "Save note" and status crowds the controls.
- Variant 4: Strong gallery-like desktop composition and readable mobile navigation. Credit appears only below the text area, weakening detail hierarchy; reset action says "Restore saved" rather than matching requested cancel language.

Visible limits: screenshots cannot prove drafts survive exhibit switches, save/cancel effects, reload verification, persistence, preservation of item/root unknown fields, or semantic labels.
